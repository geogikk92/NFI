# End-to-end проверки

## Едната команда

```bash
npm run e2e            # всички
npm run e2e sertifikati   # само тези, чието име съдържа „sertifikati"
```

Оркестраторът (`run.mjs`) прави всичко сам: мигрира базата, изчиства
остатъци от предишни пускания, засява я наново, вдига dev сървър на
**свободен** порт, изчаква го да отговаря, пуска всяка проверка в отделен
процес и накрая гаси сървъра.

Досега това бяха три ръчни стъпки в правилния ред. Пропуснатият сийд
даваше провал, който изглежда като дефект в кода.

## На ръка (за отладка на една проверка)

Пускат се срещу **`next dev`**, не срещу `next start`:

```bash
npx next dev --turbopack -p 3130     # в един терминал
npm run e2e:vhod                     # в друг
```

Защо dev, а не продукционен билд: в продукция сесийната бисквитка се казва
`__Host-nfi_session`, а браузърът приема такова име само по https. По
`http://localhost` я изхвърля мълчаливо и тестовете падат по причина, която
на Vercel не съществува.

| Команда | Какво покрива |
|---|---|
| `npm run e2e:vhod` | вход, изход, отказан достъп до /admin, невалидна и изтекла сесия |
| `npm run e2e:registraciya` | регистрация → вход → разделение на ролите |
| `npm run e2e:profil` | /profil на трите езика, пренасочване на анонимен |
| `npm run e2e:ezik` | `html lang`, немските правни страници, **шрифтовете** |
| `npm run e2e svalyane` | материали: капан за ботове, темпо, токен, истински PDF, изчерпване |
| `npm run e2e sertifikati` | сертификат: издаване → профил → сваляне → публична проверка → отмяна |

Първият път искат браузър:

```bash
npx playwright install chromium
```

Изискват и сийдната база (`npm run db:seed`) — паролата в тестовете идва
от `prisma/seed.ts`. През `npm run e2e` това става само.

## Изолация

Проверките СЪЗДАВАТ записи и част от тях се блъскат в уникални
ограничения при второто пускане: един курсист може да има само един
сертификат за курс, тоест повторното издаване пада с „вече има
сертификат" — провал, който изглежда като дефект, а е остатък.

Затова:

* всичко създадено от тестове носи маркера `e2e` в името или имейл на
  `@e2e.local` (виж `unique()` и `uniqueEmail()` в `_harness.mjs`);
* `npm run e2e:clean` трие точно тези записи и се вика сам преди всяко
  пускане;
* чистачът ОТКАЗВА да работи срещу нелокална база — изтриване по шаблон
  върху живи данни не се връща.

Проверката, че изолацията държи: два пълни пробега един след друг дават
един и същ резултат.

## Обща основа

`_harness.mjs` носи адреса (от `E2E_BASE_URL`), отчитането, пускането на
браузър със свеж контекст, вход/изход и уникалните тестови данни. Преди
него всеки файл имаше свое копие — и копията се бяха разминали: част
чакаха 2500 ms след вход, други 3000.

## Защо шрифтовете се проверяват тук

`app/layout.tsx` е замразен и вече веднъж падна на Times за целия сайт:
`--font-title` се дефинира в `:root`, а променливите стояха на `<body>`,
тоест вложеният `var()` беше невалиден и цялата стойност — празна. Нито
tsc, нито eslint, нито един снимков тест го хванаха. Само
`getComputedStyle` в истински браузър.

`e2e:ezik` пуска точно тази проверка. Всяка промяна в root layout-а минава
през него.
